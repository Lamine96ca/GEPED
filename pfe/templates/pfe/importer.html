Une ligne = une inscription. Le fichier est importé tel quel : la session, la licence, le programme et la promotion sont lus sur chaque ligne.

Comment ça marche

Le format attendu du fichier

  1. Une ligne = une inscription. Un étudiant inscrit sur 3 années a 3 lignes. Les lignes vides sont ignorées.
  2. Colonnes et valeurs obligatoires : {% for c in obligatoires %}{{ c }}{% if not forloop.last %}, {% endif %}{% endfor %}.
  3. Matricule : les inscrits ont déjà le leur, il est importé tel quel. Pour une préinscription, laissez matricule vide : il est généré = 2 derniers chiffres de la session + code du programme + compteur (4 chiffres) + code de la 1re lettre du prénom. Un préinscrit est reconnu par son ine, sinon son e-mail, sinon nom, prénom et date de naissance, pour ne pas être créé deux fois.
  4. Le programme (nom ou code), la promotion (ex. P20), la session (ex. 2025 - 2026) et la licence (ex. LICENCE 4 ou L4) doivent exister dans gePed, sinon la ligne est rejetée.
  5. Doublons : une inscription qui existe déjà (même étudiant, session et licence), dans gePed ou plus haut dans le fichier, est ignorée et l'import continue avec les autres lignes. La simulation affiche la liste des doublons ; à l'import réel (« Lancer l'import »), ils sont simplement ignorés.
  6. Un matricule inconnu crée l'étudiant ; un étudiant déjà enregistré n'est pas modifié. Préinscription : un ine déjà enregistré met la fiche de l'étudiant à jour (cases remplies du fichier), sans toucher à son matricule ni à son statut.
  7. cycle (facultatif) : DUT, Tronc commun, Licence, Ingénieur, Master ou Doctorat. Sinon, le cycle du formulaire s'applique.
  8. Sans e-mail, l'adresse matricule@etudiant.gped est générée. Dates au format JJ/MM/AAAA.
