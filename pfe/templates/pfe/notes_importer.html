Comment ça marche

Le format attendu du fichier

  1. Une ligne = une note d'un étudiant dans une matière. Les colonnes sont repérées par leur nom, dans n'importe quel ordre.
  2. Obligatoires : {% for c in obligatoires %}{{ c }}{% if not forloop.last %}, {% endif %}{% endfor %} (matiere = nom ou code). Notes : controle, tp, examen, moyenne, rattrapage (au moins une). programme si besoin de préciser.
  3. Sur 10. ABS = 0. La colonne moyenne (déposée par le programme) est prise telle quelle ; sinon elle est calculée : contrôle 25 % + TP 35 % + examen 40 % (sans TP : 40 % + 60 %). Si la moyenne est remplie et que contrôle, TP et examen valent tous 0, ces 0 sont considérés comme vides.
  4. rattrapage : on garde la meilleure des deux notes, avec la mention « Session ».
  5. Arrêtés 879 (Licence) et 878 (DUT) : mêmes colonnes et mêmes calculs, pour les étudiants dont la première inscription dans le cycle date de 2026-2027 ou après (art. 89 et 88) ; les étudiants déjà inscrits avant gardent les anciennes règles.
  6. Arrêté 877 (Tronc commun et cycle Ingénieur, depuis 2025-2026) : cc (ou controle) = contrôle continu, ct (ou examen) = contrôle terminal ; moyenne = CC 40 % + CT 60 % (un TP donné entre dans le CC) ; le rattrapage retenu est plafonné à 5. Le règlement est trouvé d'après l'inscription de chaque étudiant : le même fichier sert pour tous les cycles. Les intitulés des enseignants sont reconnus : « CC (40 %) », « Note CC », « C.C. », « Contrôle continu », « CT (60 %) », « Contrôle terminal »…
  7. Fiche enseignant gePed ({% if profil.telecharge_fiches %}Saisie des notes, bouton Excel de chaque matière{% else %}téléchargée par le chef de département ou le directeur de programme{% endif %}) : colonnes CC / TP / CT pour les arrêtés 877, 878 et 879, Contrôle / TP / Examen pour les autres. Elle porte un code de contrôle calculé à partir des notes : saisissez celui de la fiche signée ; s'il ne correspond pas au fichier, l'import est annulé jusqu'à correction.
  8. Fiche de l'enseignant acceptée telle quelle : un titre au-dessus du tableau (la ligne d'en-têtes est celle qui contient « matricule »), des colonnes d'information (prénom, nom, téléphone, N°…) et une zone de signature sous le tableau ne gênent pas l'import.
  9. La matière est cherchée dans le programme et la licence de l'inscription de l'étudiant pour la session. Une note déjà enregistrée est mise à jour (modification tracée) ; une ligne répétée est ignorée.
    10. {% if not mes_programmes %}
  10. Étudiant non inscrit dans la session : il y est inscrit automatiquement si la matière est unique dans la session (sinon ajoutez la colonne programme) et si toutes ses notes de la session sont du même programme et de la même licence. Jamais pour un préinscrit ni pour un étudiant déjà inscrit dans la session. La simulation liste ces inscriptions avant l'import.
    11. {% endif %} {% if profil.est_scolarite %}
  11. Année en cours (délibérée ou non) : les notes sont créées ou mises à jour. Année écoulée : les notes manquantes sont créées ; une note déjà enregistrée n'est modifiée que par le chef de la scolarité.
    12. {% else %}
  12. Semestre non délibéré de l'année en cours : les notes sont créées ou mises à jour. Semestre délibéré ou année écoulée : lignes refusées, sauf pendant une autorisation du chef de la scolarité.
    13. {% endif %}
  13. Le fichier importé et le PDF de l'enseignant sont gardés avec l'import (jamais remplacés) ; le PDF sert de justificatif à chaque note modifiée.{% if mes_programmes %} Votre périmètre : si une ligne concerne un autre programme, tout l'import est refusé.{% endif %}
